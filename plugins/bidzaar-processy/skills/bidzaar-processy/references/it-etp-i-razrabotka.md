Источник: база знаний iSpring, пространство «6. Департамент ИТ ЭТП», статья

Департамент занимается развитием, поддержкой и аналитикой ЭТП — самой площадки
Bidzaar. Формулировка из статьи: «команда, которая стоит за каждым пикселем и строкой
кода нашей ЭТП».

**Цель.** Чтобы заказчик получил стабильный, понятный и мощный инструмент. Отсюда
практика: команда погружается в рабочие процессы пользователей, а не только в
функциональность.

## Семь отделов

| Отдел | Чем занимается |
|---|---|
| **Внутренняя автоматизация** | Разработка для внутренних нужд компании |
| **Аналитика** | Следит за метриками использования функций, определяет направления развития продукта, даёт руководству данные для стратегических решений |
| **Разработка** | Новый функционал, исправление ошибок, **релизы каждые полтора месяца** |
| **Техническая поддержка** | Решает проблемы пользователей, передаёт сложные случаи разработчикам, собирает обратную связь |
| **Тестирование** | Проверяет все сценарии, включая экстремальные, оценивает удобство интерфейса, следит, чтобы новые функции не сломали старые |
| **ИИ** | Создаёт и внедряет машинные модели под прикладные задачи бизнеса |
| **DevOps** | Стабильная работа серверов, бесперебойные обновления |

Отдельное пространство **«6.1 Отдел аналитики»** содержит 102 материала — это
крупнейший блок департамента и он в этот скилл не разобран.

## Цикл выпуска функционала

```
Идея (от клиентов, коллег или аналитики)
  → Проектирование (как это будет работать технически)
  → Разработка (написание кода)
  → Тестирование (проверка всех сценариев)
  → Релиз (выпуск обновления + обучение коллег)
  → Мониторинг (как пользователи воспринимают нововведение)
```

Два места, где этот цикл стыкуется с остальной компанией:

- **Вход — «Идея от клиентов»**: заказчик просит доработку → CSM или Сейл фиксирует →
  РОП решает, выносить ли на **питчинг** → продуктовый бэклог. См.
  `references/prodazhi-i-aktivaciya.md` и `references/kommunikacii-i-raskrytie.md`
  (доработки — жёлтая зона, кастом обещать нельзя).
- **Выход — «Релиз + обучение коллег»**: релиз каждые полтора месяца, о нём
  оповещаются заказчики через чат «Старкомбиз» (руководители CSM отправляют
  согласованное сообщение для рассылки со стороны Sale).
