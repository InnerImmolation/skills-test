# SRM: статусные модели процессов

Источник: схемы статусных моделей из SRM Yonote (excalidraw), выгрузка от 13.08.2026 —
«заявка на потребность», «закупочная процедура», «протокол», «договор», «заказ»

SRM — отдельный продукт для внутренних закупочных процессов заказчика: заявка на
потребность проходит согласование, превращается в закупочную процедуру, процедура
выгружается на Bidzaar, результаты возвращаются в SRM протоколом, дальше договор и заказ.

Внешние системы в контуре: **Bidzaar** (ЭТП, туда уходят процедуры и оттуда приходят
заявки участников), **Tessa** (согласование договоров и протоколов), **ERP** (заказы).

> Проектная документация по внедрениям SRM у конкретных заказчиков в скилл не вошла:
> это документация проектов, а не внутренние процессы компании.

## Сквозная цепочка

```
Заявка на потребность
      │ передано на тендер
      ▼
Закупочная процедура ──выгрузка──► Bidzaar ──заявки участников──► расчёт критериев
      │ определены основной и резервный поставщики
      ▼
Протокол ──согласование (Tessa или SRM)──► утверждён ──результаты──► Bidzaar
      │
      ▼
Договор ──согласование в Tessa──► подписан
      │
      ▼
Заказ ──► ERP
```

## Заявка на потребность

**Этап 1. Формирование**

| Статус | Что значит |
|---|---|
| **Проект** | Заявка сформирована, но не отправлена на согласование. Доступно редактирование и прикрепление документации |
| **На доработке** | Возникает в трёх случаях: инициатор отозвал заявку на доработку; менеджер закупок отклонил заявку; по результатам согласования один из согласующих отклонил заявку |

**Этап 2. Согласование**

| Статус | Что значит |
|---|---|
| **На согласовании** | Заявка отправлена на согласование в соответствии с картой маршрута |
| **Отзыв с согласования** | Заявка в статусе «Проект» возвращается инициатору |
| **Согласована** | Заявка согласована и передана сотруднику ОЦО для подбора источника поставки |

**Этап 3. Определение ответственного**

| Статус | Что значит |
|---|---|
| **На анализе** | Заявка передана менеджеру закупок. Проводится анализ: определяется, позиция «на закупку» или «на поставку», и является ли заявка низкостоимостной |
| **Запрос информации** | Менеджер закупок запросил информацию у инициатора |
| **Передано на тендер** | По заявке создана закупочная процедура |
| **Обработана** | По заявке согласован протокол. Заявка включена в заказ (если заявка с признаком «на закупку») |

Развилка анализа даёт два типа: **заявка на поставку** и **заявка на закупку**.

## Закупочная процедура

**Этап 1. Формирование**

| Статус | Что значит |
|---|---|
| **Проект** | Доступно: добавление потребностей в процедуру, высвобождение позиций по запросу на закрытие потребности, изменение менеджера закупок |
| **Отправлена в Bidzaar** | Черновик выгружен в Bidzaar. Доступно изменение процедуры |

**Этап 2. Приём предложений**

| Статус | Что значит |
|---|---|
| **Приём предложений** | Процедура опубликована на Bidzaar. Доступно внесение изменений |
| **Обновление приостановлено** | На стороне ЭТП внесены существенные изменения по процедуре. Менеджеру закупок отправлено уведомление |
| **Переторжка** | Подготовка переторжки и публикация. Процедура переведена на этап приёма предложений |
| **Внесение изменений** | Статус новой версии процедуры при внесении изменений |

**Этап 3. Подведение итогов**

| Статус | Что значит |
|---|---|
| — | Приём предложений завершён, заявки участников загружены из Bidzaar |
| **Техническая оценка** | Процедура и заявки участников на оценке по соответствию ТЗ у инициатора либо менеджера закупок |
| **Обработка аналогов** | Процедура и заявки на оценке аналогов у инициатора либо менеджера закупок |
| **Обработка сотрудником СБ** | Запущен маршрут обработки контрагентов по критериям «Аффилированность» и «ИДО» сотрудником службы безопасности |
| **Идёт расчёт критериев** | Выполняется расчёт критериев по предложениям участников. По результатам определяются **основной** и **резервный** поставщики |

## Протокол

| Этап | Статус | Что значит |
|---|---|---|
| 1. Формирование | **Проект** | Протокол сформирован, доступна отправка на согласование |
| 2. Согласование | **На согласовании** | Документ в процессе согласования |
| | **На доработке** | Менеджер закупок отозвал протокол с согласования |
| | **Утверждён** | Документ утверждён председателем |
| | **Ошибка интеграции** | Ошибка при интеграции со смежными системами |
| 3. Закупка завершена | **Результаты отправлены** | Результаты процедуры опубликованы на Bidzaar |
| | **Процедура завершена** | Процедура завершена, участникам отправлены уведомления |

**Важная развилка по маршруту согласования:**

> Согласование протокола по **низкостоимостной** закупочной процедуре (до 1 млн ₽) —
> в SRM. Остальные протоколы — в смежной системе **Tessa**.

## Договор

| Этап | Статус | Что значит |
|---|---|---|
| 1. Формирование договора | **Проект** | Создана карточка договора |
| 2. Согласование | **На согласовании** | Договор отправлен на согласование в смежную систему Tessa |
| | **Не согласован** | Договор не согласован в Tessa |
| | **Ошибка интеграции** | Ошибка при интеграции со смежными системами |
| 3. Договор заключён | **Подписан** | Договор согласован в Tessa, результаты согласования загружены в SRM. Доступно создание заказа |
| | **Не действует** | После наступления даты «Действует по» |

Согласование договора происходит в смежной системе Tessa. Аналогично работают
**рамочный договор**, **спецификация** и **ценовая спецификация**.

## Заказ

| Этап | Статус | Что значит |
|---|---|---|
| 1. Формирование | **Проект** | Карточка заказа сформирована |
| 2. Обработка | **На согласовании** | Заказ отправлен на согласование в соответствии с картой маршрута в SRM |
| | **На доработке** | Менеджер снабжения на этапе согласования вернул заказ на доработку |
| | **Ошибка интеграции с ERP** | Ошибка при интеграции со смежными системами |
| 3. Завершён | **Отправлено в ERP** | Заказ отправлен в смежную ERP-систему |

## ⛔ Нет в документах

- Кто и в какой срок разбирает статус «Ошибка интеграции» — он есть в трёх моделях
  из пяти, обработчик не назван нигде
- Что происходит с процедурой в статусе «Обновление приостановлено»: кто принимает
  решение возобновить и в какой срок
- Кто такой «председатель», утверждающий протокол, — роль не расшифрована
- Пороги и правила определения «низкостоимостной» закупки, кроме суммы до 1 млн ₽
- Карта маршрута согласования — упоминается в трёх моделях, самой карты в документах нет
